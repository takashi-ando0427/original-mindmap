# 記事執筆（記事生成担当）

`note事業部/CLAUDE.md`（全体ルール）と `note事業部/2_記事生成/CLAUDE.md`（担当ルール）を必ず守る。

- **インプット**：`1_リサーチ/（テーマ名）リサーチ結果/` の3ファイル
  （`youtube_リサーチ.md` / `x_リサーチ.md` / `deep_リサーチ.md`）
- **出力先**：`2_記事生成/（テーマ名）記事.md`
- **図表の画像**：`2_記事生成/（テーマ名）図1.png`（連番）

## ステップ0：材料をそろえる
1. リサーチ結果の3ファイルを全部読む。要点・共通点の表・数字・出典を手元に置く
2. 足りないファイルがあれば、想像で埋めずに「足りない」と報告して止まる
3. 【要確認】本文を書き始める前に、ユーザーに「自分の体験」を**1つだけ**質問する
   - 聞き方の例：「この記事に入れられる、たかしさんご自身の体験を1つ教えてください。
     うまくいった話でも、失敗した話でも構いません」
   - 返ってきた体験だけを使う。体験していないことを体験したように書かない

## ステップ1：目次をつくる
- リサーチの構成案をもとに、章立て（見出し）を並べる
- 見出しの階層は2段まで
- この時点で本文は書かない。ユーザーに目次を見せて方向を確認する

## ステップ2：細分化する
- 各章について、何を書くかを箇条書きに落とす
  （その章の結論 / 理由 / 具体例 / 使う数字と出典 / 図表の要否）
- 「この章でわかること」の一言を、章ごとに決めておく
- 構成を勝手に省かない。要点は全部カバーする

## ステップ3：章ごとに書く
1章ずつ書く。まとめて書かない。各章で次を守る。

- 章のあたまに「この章でわかること」を一言入れる
- 結論 → 理由 → 具体例の順で書く
- 専門用語は必ず「簡単に言うと〜」で噛み砕く
- 手順は、読者がそのとおりに手を動かせる粒度まで降ろす
- 1文は短く。1つの文で2つ言おうとしない
- 「これ」「それ」「やつ」を使わない。直前に出した名前でも、もう一度名前で呼ぶ
- 「寝てる間に」「放置で」などのクリシェ、「すごい」「便利」だけの感想を使わない
- 数字は必ず出典つき。根拠のない数字は書かない

## ステップ4：図表を入れる
- 2つ以上を比べる箇所は、文章で並べずに必ず表にする
- 手順の流れ・全体像・数の変化は図にする
- 表や図は画像として書き出し、`（テーマ名）図1.png` の形で保存して記事に差し込む
- 画像にはキャプションを1行つけ、直後に「そこから何が言えるか」を1文書く
- 図表の数字は本文と一致させる。飾りの画像は置かない

## ステップ5：目次にリンクを張る
- 記事の冒頭に目次を置き、項目から各見出しへ飛べるようにする
- 下書きではアンカーリンクで書く
  例：`- [ChatGPTでできること](#chatgptでできること)`
- 目次の文言は本文の見出しと一字一句そろえる
- 章を足したり消したりしたら、目次も同時に直す

## ステップ6：無料部分を整える
購入前に読める範囲で、次を満たす。

- 読者のモヤモヤを、こちらから先に言語化する
- 読んだあとどうなれるのか（未来）を見せる
- 「この人が言うなら」と思える実体験（ステップ0で聞いたもの）を入れる
- 意味のない前置きを書かない。冒頭の一文で離脱される

## 仕上げ
- 全体を通しで読み、同じものを同じ名前で呼べているか確認する
- 完成したら `2_記事生成/（テーマ名）記事.md` に保存し、`3_タイトル` へ渡す
- 迷ったところは、勝手に決めずに質問する
