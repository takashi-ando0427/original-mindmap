## 1. エフォート（effort）とは何か

Claude が1回の返答に **どれだけトークンを使うか＝どれだけ手間をかけるか** を選ぶ設定。
公式ドキュメントの説明では、応答の丁寧さとトークン効率のトレードオフを、
モデルを変えずに1つのつまみで調整するもの。

重要な性質（公式ドキュメントより）：
- 効くのは思考部分だけではない。**返答の文章、ツール呼び出しの引数、思考のすべて**に効く
- 思考（thinking）が有効でなくても効く
- **厳密なトークン上限ではなく「behavioral signal（振る舞いの目安）」**。
  低いレベルでも、難しい問題では考える。ただし高いレベルより考える量は少なくなる

出典：https://platform.claude.com/docs/en/build-with-claude/effort

## 2. レベルは5段階（API）

| レベル | 公式の説明 | 想定用途 |
|---|---|---|
| `max` | 制約なしで能力を最大化 | 最も深い推論と徹底的な分析が要るタスク |
| `xhigh` | 長時間の作業向けの拡張 | 30分を超える長時間のエージェント／コーディング作業 |
| `high` | 高い能力。**パラメータを指定しないのと同じ** | 複雑な推論、難しいコーディング、エージェント作業 |
| `medium` | バランス型。中程度のトークン節約 | 速度・コスト・性能のバランスが要るエージェント作業 |
| `low` | 最も効率的。大きな節約と引き換えに能力は少し下がる | 単純なタスク、サブエージェントなど速度と低コスト優先 |

- **APIのデフォルトは `high`**。`high` を指定することと、指定しないことは完全に同じ挙動。
- `xhigh` は後から追加されたレベル。`max` に対応していても `xhigh` に対応しないモデルがある。

出典：同上

## 3. 対応モデル（公式ドキュメント記載のまま）

`claude-fable-5`, `claude-mythos-5`, `claude-mythos-preview`, `claude-opus-5`,
`claude-opus-4-8`, `claude-opus-4-7`, `claude-opus-4-6`, `claude-sonnet-5`,
`claude-sonnet-4-6`, `claude-opus-4-5-20251101`

対応プラットフォーム：Claude API、Claude Platform on AWS、Amazon Bedrock、Google Cloud、Microsoft Foundry
ベータヘッダーは不要（正式機能）。

`xhigh` 対応：Fable 5 / Mythos 5 / Opus 5 / Opus 4.8 / Opus 4.7 / Sonnet 5
`max` 対応：上記に Opus 4.6 / Sonnet 4.6 / Mythos Preview を加えたもの

出典：同上

## 4. モデル別の公式推奨（要点）

| モデル | 公式の出発点 | 補足 |
|---|---|---|
| Claude Opus 5 | **`high`（デフォルト）から始める** | 難しいコーディングは `xhigh`、正しさ最優先なら `max`。`low`/`medium` はコストと応答時間の主要な制御手段として積極的に使ってよい |
| Claude Opus 4.8 / 4.7 | **コーディングとエージェント作業は `xhigh` から** | 他の知能重視の作業は `high`。下げるのは評価で品質が保てると測ってから |
| Claude Sonnet 5 | デフォルトは `high` | `medium` は「Sonnet 4.6 の high 相当」のコスト削減の一段下げ |
| Claude Sonnet 4.6 | 推奨デフォルトは **`medium`** | デフォルトは `high` だが、明示指定しないと想定外の待ち時間が出るため |
| Claude Fable 5 | `high`（デフォルト）から | 低いレベルでも、前世代モデルの `xhigh` を上回ることが多い |

Opus 5 特有の注意：
- **エフォートは思考量を変えるが、見える返答の長さは確実には短くならない。**
  短くしたいならプロンプトで指示する
- `xhigh` と `max` では thinking を無効化できない（400エラー）

出典：同上

## 5. ツール（エージェント）作業での効き方

公式ドキュメントが挙げている、レベルによる振る舞いの違い。

**低いエフォート**
- 複数の操作を1回のツール呼び出しにまとめる
- ツール呼び出しの回数が減る
- 前置きなしで作業に入る
- 完了報告が簡潔

**高いエフォート**
- ツール呼び出しの回数が増える
- 作業前に計画を説明する
- 変更点の詳細な要約を出す
- コードコメントが充実する

出典：同上

## 6. コスト・速度への影響（公式に書かれている範囲）

- 思考トークンは**出力トークンとして課金される**（Claude Code のコスト削減ドキュメント）
- エフォートを下げると、応答時間とコストを大きく減らせる（公式のベストプラクティス）
- **会話の途中でエフォートを変えるとプロンプトキャッシュが効かなくなる。**
  長いセッションでキャッシュに頼るなら、最初に決めて変えない
- `xhigh` / `max` で動かすときは `max_tokens` を大きく取る（64k から調整が目安）

出典：https://platform.claude.com/docs/en/build-with-claude/effort
　　　https://code.claude.com/docs/en/costs

## 7. Claude Code 側の設定（コマンドライン版）

- `/effort` で選ぶ。`/model` のピッカーからも変更できる
- 起動時フラグ `claude --effort high`、環境変数 `CLAUDE_CODE_EFFORT_LEVEL`、
  設定ファイルの `effortLevel` / `modelSettings` でも指定できる
- 優先順位は「環境変数・CLIフラグ・/effort による明示指定 ＞ 保存された設定 ＞ モデルの既定値」
- モデルが対応していないレベルを指定すると、対応する最も高いレベルに落ちる
- Claude Code には `ultracode`（xhigh を送りつつ動的ワークフローを組む）と、
  デフォルトに戻す `auto` もある
- 単発で深く考えさせたいときは、プロンプトに `ultrathink` と書く方法がある
  （セッションのエフォート設定自体は変わらない）

出典：https://code.claude.com/docs/en/model-config
　　　https://code.claude.com/docs/en/costs

## 9. なぜこのテーマが伸びうるのか（仮説）

**注意：本来は「伸びている発信」を YouTube と X で観測して抽象化する工程。
その観測ができていないため、以下は公式情報からの推測であり、伸びの裏付けはない。**

- 「モデルを変える」以外にコストを下げる手段があると知られていない
- 高い設定＝良い、と思い込みやすいが、公式は「考えすぎ」「過剰」を明確に注意している
- 設定箇所が多い（コマンド／フラグ／環境変数／設定ファイル）ため、迷いやすい

## 10. 想定読者とその悩み（会社全体ルールより）

- 読者：これから副業を始めたい会社員。ChatGPT は触ったことがあるが、それ以上のツールは知らない
- 悩みの仮説：AIに課金したが、何にいくら使っているのか分からない。設定画面の用語が分からない
- **懸念（要相談）**：エフォートは開発者向けの設定であり、
  「ChatGPT しか触ったことがない読者」との距離が大きい。
  記事にするなら「AIに“どれだけ考えさせるか”を選ぶつまみ」という切り口に絞る必要がある

## 11. 記事で答えること（結論の案）

「エフォートは、AIにどれだけ手間をかけさせるかを選ぶつまみ。
迷ったら high のままでよく、簡単な作業や急ぎのときだけ下げれば、待ち時間と費用が減る」
