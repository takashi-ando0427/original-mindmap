# note事業部

## 概要
note（ https://note.com/ ）での情報発信を事業として立ち上げるための作業フォルダです。
記事の企画・執筆・公開・振り返りまでを、このフォルダ配下で一元管理します。

## 目的
- 発信テーマとターゲットを定義し、属人的でない運用ルールを整備する
- 記事のネタ出しから公開までのフローをリポジトリ上で可視化・記録する
- 公開後の反応（ビュー・スキ・フォロワー等）を蓄積し、次の企画に活かす

## フォルダ構成
記事づくりの工程を、5つの役割フォルダに分けて管理します。番号順に進めるのが基本フローです。

```
note事業部/
├── CLAUDE.md        # 事業部全体の共通ルール（発信者・読者・文体・禁止事項）
├── README.md        # 本ファイル（事業部の概要・運用ルール）
├── 1_リサーチ/      # ネタ出し、想定読者・切り口・構成案の決定
├── 2_記事生成/      # 構成案をもとにした本文の執筆
├── 3_タイトル/      # タイトル・見出し・導入文の作成と選定
├── 4_品質チェック/  # 事実・表現・体裁・権利の最終確認
└── 5_SNS集客/       # 公開後の告知と反応の記録
```
各フォルダには `CLAUDE.md`（その担当が守るルール）、`README.md`（役割・インプット／アウトプット・ファイル命名規則）、
`.claude/skills/`（その担当の作業手順スキル）を置いています。

## 共通ルール
発信者・読者・文体・書いてはいけないこと・仕事の進め方は、直下の `CLAUDE.md` にまとめています。
どの工程を担当する場合も、作業前に必ず目を通してください。
各担当は、事業部全体のルールを守ったうえで、担当フォルダ内の `CLAUDE.md` を追加で守ります。

## 記事を1本作るとき
スキル `make-note` が、1_リサーチ → 5_SNS集客 の5工程を順番に回します。
`/make-note` で呼び出してください（定義：`.claude/skills/make-note/SKILL.md`）。

| 工程 | 担当スキル | 成果物 |
|---|---|---|
| 1 | `neta-shushu`（ネタ収集） | `1_リサーチ/（テーマ名）リサーチ結果/` の3ファイル |
| 2 | `write-article` | `2_記事生成/（テーマ名）記事.md` |
| 3 | `title-ideas` | `3_タイトル/（テーマ名）タイトル案.md` |
| 4 | `quality-check` | `4_品質チェック/（テーマ名）検査結果.md` ＋記事本体の修正 |
| 5 | `threads-promo` | `5_SNS集客/（テーマ名）スレッズ宣伝.md` |

各工程の途中には確認ポイントがあり、ユーザーの返事を待ってから次へ進みます。
単体で呼ぶこともできます（例：タイトルだけ作り直す）。

## 運用ルール（たたき台）
- 成果物は Markdown（`.md`）で作成し、ファイル名は担当ごとに次で統一する
  （`1_リサーチ/（テーマ名）リサーチ結果/` の3ファイル、`（テーマ名）記事.md`、
  `（テーマ名）タイトル案.md`、`（テーマ名）検査結果.md`、`（テーマ名）スレッズ宣伝.md`）
- 1本の記事に関する成果物は、同じ「テーマ名」の表記で各工程フォルダに揃える
- 公開した記事は、下書きの冒頭に公開URLを追記する
- 数値の振り返りは公開から1週間後・1か月後の2回を目安に `5_SNS集客/（テーマ名）スレッズ宣伝.md` へ追記する
