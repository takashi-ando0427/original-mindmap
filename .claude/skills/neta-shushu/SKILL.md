# ネタ収集（リサーチ担当）

`note事業部/CLAUDE.md`（事業部全体）と `note事業部/1_リサーチ/CLAUDE.md`（担当ルール）を守ったうえで実行する。
成果物は `note事業部/1_リサーチ/YYYY-MM-DD_テーマ名_research.md` に保存する。

以下の3経路から収集する。**最低でも2経路は必ず使う**（1つだけだと切り口が偏るため）。

## 1. YouTube（使用ツール：yt-dlp）

yt-dlp を使って、伸びている動画の「中身」をまとめて収集する。
再生数が多いだけの動画は対象外。次の条件で絞り込む。

- 最近投稿された動画であること
- チャンネルの登録者数が少ないこと
- それにもかかわらず再生が伸びていること

理由：登録者が多いチャンネルは人気だけで伸びるため除外する。これにより「中身が良くて伸びた動画」だけが残る。

### 手順
1. キーワードで候補を集める（投稿日順の検索を使う）
   ```
   yt-dlp --flat-playlist --dump-json "ytsearchdate100:AI 副業" > candidates.jsonl
   ```
2. 各候補の詳細（登録者数・再生数・投稿日）を取り、上の3条件で絞る
   ```
   yt-dlp --dump-json "<動画URL>"
   ```
   参照するフィールド：`upload_date`（投稿日）、`view_count`（再生数）、`channel_follower_count`（登録者数）
3. 残った動画の「中身」を字幕で取得する
   ```
   yt-dlp --skip-download --write-auto-subs --sub-lang ja --convert-subs srt "<動画URL>"
   ```
4. 字幕を読み、何を・どの順で話しているか（構成）と、伸びた理由の仮説を書く

### 絞り込みの目安（たたき台。運用しながら調整する）
- 投稿日：直近6か月以内
- 登録者数：1万人未満
- 伸び：再生数 ÷ 登録者数 が3倍以上

※ フィールド名や閾値は初回実行時に実データで確認する。取得できない項目があれば、想像で埋めずに「取れなかった」と記録する。

## 2. X（使用ツール：claude-in-chrome）

claude-in-chrome（Chromeブラウザ操作）を使い、実際にログインした状態のXで収集する。
いいね数・フォロワー数まで確認しながら集める。

- 検索したキーワードと、確認した投稿のURLを必ず残す
- 数字（いいね数・フォロワー数）は画面で見たまま記録する。丸めない
- フォロワーが少ないのに反応が多い投稿を優先する

## 3. ネット検索（ディープリサーチ）

即答せず、数十ページ規模の情報源を読み込んだうえで、1本のレポートにまとめる。

- 1〜2ページ読んで結論を出さない
- 同じ主張が複数の情報源で出てきたら、その旨を明記して重く見る
- 出典URLを必ず全て残す

## まとめ方

`1_リサーチ/CLAUDE.md` のとおり、拾ったものを並べるだけにしない。

成果物には次を含める。
1. **共通点の表**：複数の経路・発信で共通して出てきた内容を必ず表にする
   （項目例：主張 / 出てきた経路 / 出典URL / 数字）
2. **なぜ伸びているのかの抽象化**：個別の事例ではなく、共通する構造を言葉にする
3. **想定読者とその悩み / 記事で答えること（結論）**
4. **構成案**（見出しレベルの箇条書き）
5. **出典一覧**（全URL）

## やってはいけないこと

- 見つからなかったときに、それらしい例を作らない。「足りない」と報告する
- 数字を丸めたり盛ったりしない
- リサーチの段階で記事を書き始めない（本文は `2_記事生成` の担当）
